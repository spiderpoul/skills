# Доказательства и адаптация

Примеры условные. Используй их форму; пути, команды и приоритеты определяй по обследуемому проекту.

## Замечание с доказательством

**P0 · E2 · scripts/check.js:1–2**

- Факт: обязательный `check` только печатает успех и завершает процесс с кодом 0; ни одно условие не проверяется.
- Последствие: даже невыполненная задача получает зелёный статус.
- Минимальное исправление: заменить заглушку проверкой указанного в документации свойства; недоступную проверку возвращать как явный неуспех.
- Приёмка: намеренная релевантная поломка даёт ненулевой код и сообщение о причине; рабочий вариант проходит.

**P1 · B2 · CONTRIBUTING.md и docs/design.md**

- Факт: первый документ требует использовать обработчик A, второй называет A устаревшим и требует B. Оба правила относятся к новому коду; порядок их применения не определён.
- Последствие: агент выбирает несовместимый образец по своему усмотрению.
- Минимальное исправление: определить действующий подход и границы legacy, оставить одну версию правила со ссылкой.
- Приёмка: выбранная типовая задача приводит к одному актуальному образцу, подтверждённому кодом/тестом.

## Неподтверждённое вместо обвинения

«CODEOWNERS есть, настройки защищённой ветки недоступны. Обязательность approval не подтверждена» — корректно. «Ревью можно обойти» без чтения настроек — недоказанная находка.

«Скиллов не найдено в обследованной области, но повторяющаяся проблема не выявлена» — не основание предложить новый скилл.

Найденный конфликт инструкций — доказанный пробел; без исходной попытки утверждение «именно он вызвал ошибку агента» остаётся гипотезой.

## Разные типы проектов

| Проект | Типовая задача | Общая зона | Доказательство результата |
|---|---|---|---|
| Python-сервис | изменить ответ API | схема, SDK, клиенты | контрактные сценарии, ошибки и совместимость |
| CLI | добавить параметр команды | parser, help, скрипты пользователей | вывод, exit code, неверный ввод, регрессии старого вызова |
| Мобильное приложение | изменить экран | навигация, состояние, API | сценарии устройства/эмулятора и тесты затронутого поведения |
| Библиотека | расширить публичный метод | экспорты, типы, потребители | контракт, примеры, совместимость существующих вызовов |
| Монорепозиторий | изменить общий конфиг | зависимые пакеты | выбранные потребители, их сборки и интеграционные сценарии |

Для маленькой библиотеки подробная ролевая схема и браузер не нужны. Для системы с несколькими продуктами одной сборки изменённого пакета может быть недостаточно. Любой вывод ограничивай фактически прочитанной выборкой.
