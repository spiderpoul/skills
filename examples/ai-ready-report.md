# Пример отчёта ai-ready-check

Это иллюстрация формата на **вымышленном Python-сервисе**, а не результат аудита этого репозитория. Пути, строки и задача условные.

## Вывод

В проекте есть короткая карта кода, актуальный контракт API и ответственный за изменения. Основной пробел: документированная проверка тестов скрывает ошибку запуска. Поэтому агент может объявить изменение готовым, не подтвердив критерии приёмки.

## Область

- Проект: `invoice-service`, условный снимок `example-snapshot` без Git-истории.
- Прочитано: `CONTRIBUTING.md`, `docs/api.md`, `tasks/INV-12.md`, `service/`, `tests/`, `scripts/check.sh`.
- Задача: вернуть пустой список счетов для существующего клиента без счетов, сохранив ответ 404 для отсутствующего клиента.
- Режим: статический аудит. Проверки продукта не запускались; настройки удалённого CI недоступны.

## Маршрут задачи

INV-12 → контракт в `docs/api.md` → обработчик и актуальный тест → потребители API и CSV → сценарии пустого результата и отсутствующего клиента → `scripts/check.sh` → отчёт и ревью владельца.

Для общей функции прочитаны оба заявленных внутренних потребителя. Внешние клиенты не обследованы. Это разбор артефактов, а не выполненная реализация INV-12.

В промпт вручную пришлось бы добавлять правило «проверь фактический результат pytest, не верь сообщению скрипта». Правильнее исправить сам gate и связать команду с результатом, чтобы это правило не зависело от памяти автора промпта.

## Находка

**P0 · E2 · scripts/check.sh:2–3 — обязательная проверка скрывает ошибку**

Условный фрагмент проверяемого файла:

```sh
#!/bin/sh
python -m pytest || true
echo 'Checks passed'
```

**Доказательство:** ошибка pytest подавляется `|| true`; последняя команда успешна. В `CONTRIBUTING.md:8` именно этот скрипт определён как обязательная проверка.

**Последствие:** регрессия ответа 404 или CSV-экспорта может получить ложный зелёный статус.

**Минимальное исправление:** передать ненулевой код pytest вызывающему процессу и печатать успех только после успешных тестов.

**Приёмка:** намеренно сломанный тест даёт ненулевой exit code и не печатает `Checks passed`; рабочий вариант проходит. Отдельно подтвердить, что CI использует исправленный скрипт.

## Порядок исправления и непроверенное

1. Исправить передачу результата в `scripts/check.sh`.
2. Подтвердить поведение на рабочем и заведомо падающем тесте.
3. Проверить подключение команды в CI и сохранить фактический результат INV-12.

Не подтверждены: запуск тестов, рабочая среда, удалённый CI, обязательность ревью и история согласования. Статический аудит не подтверждает, что сервис работает после изменения.
