# Skills для агентной разработки

Практики, которые помогают агенту найти правильный образец, сохранить границы задачи и проверить результат.

Автор — [Павел Уваров](https://github.com/spiderpoul). Материалы к докладу **«Не Claude единым: агентная разработка в закрытом контуре большого фронтенда»**.

## Начать за минуту

Из корня проекта, который хотите проверить:

```bash
npx skills add spiderpoul/skills --skill ai-ready-check
```

Выберите своего агента в установщике, затем попросите его:

```text
Используй ai-ready-check. Проверь этот проект на готовность к агентной разработке.
Ничего не меняй. Покажи доказанные проблемы, приоритеты и минимальный план исправлений.
```

Установщик — [Skills CLI](https://github.com/vercel-labs/skills). Команда устанавливает скилл в текущий проект; `--global` устанавливает его для пользователя. Можно указать агент явно:

```bash
npx skills add spiderpoul/skills --skill ai-ready-check --agent codex
npx skills add spiderpoul/skills --skill ai-ready-check --agent claude-code
npx skills add spiderpoul/skills --skill ai-ready-check --agent opencode
```

Для установки нужен Node.js с npm и доступ к публичным npm/GitHub. Сам скилл — Markdown: после копирования ему не нужны Node.js или пакеты из этого репозитория.

## Что здесь есть

| Скилл | Когда использовать | Результат |
|---|---|---|
| [ai-ready-check](skills/ai-ready-check/SKILL.md) | подготовить проект к агентной работе или разобраться в повторяющихся ошибках агента | состояние восьми областей, доказанные замечания P0/P1/P2, минимальные исправления и критерии их приёмки |

Первый скилл подходит для разных стеков и размеров проекта. Он проверяет инструкции, документацию, задачи и приёмку, cross-zone, проверки, инструменты, скиллы и независимое ревью. Отсутствие OpenSpec, MCP или субагентов само по себе не считается проблемой.

По умолчанию аудит только читает файлы. Скилл не меняет проект, не запускает его проверки, не публикует сообщения и не создаёт PR. Это инструкция агенту; технические ограничения задаются его клиентом и окружением.

Скилл отличает реальный пробел от недоступной информации. Он не выдаёт процент «AI-ready» и не подменяет проверку продукта общей оценкой репозитория.

## Установка вручную и закрытый контур

Скопируйте **весь каталог** `skills/ai-ready-check`, включая `references/` и `agents/`, в каталог скиллов своего клиента. Не ограничивайтесь одним `SKILL.md`.

| Клиент | Каталог в проекте |
|---|---|
| Codex | `.agents/skills/ai-ready-check/` |
| Claude Code | `.claude/skills/ai-ready-check/` |
| OpenCode | `.agents/skills/ai-ready-check/` |

Пути и параметры установщика приведены по [документации Skills CLI](https://github.com/vercel-labs/skills#supported-agents). Для другого клиента выберите его поддерживаемый каталог. Если загрузка скиллов не поддерживается, попросите агента прочитать `SKILL.md` и указанные в нём справочники по локальному пути.

В закрытом контуре перенесите каталог через принятый в команде процесс. Для выполнения аудита внешние ссылки из материалов доклада не требуются. Конкретные доступы к задачам, CI и диагностике определяет среда проекта.

## Примеры запуска

**Общий аудит:**

```text
Используй ai-ready-check. Проверь репозиторий статически.
Выбери одно документированное типовое изменение и проследи путь от задачи до приёмки.
```

**Повторяющаяся ошибка:**

```text
Используй ai-ready-check. Агент копирует устаревшие примеры и меняет общий код вне задачи.
Найди подтверждённые причины в контексте проекта. Предложи минимальные исправления.
```

**Передача задач:**

```text
Используй ai-ready-check. Возьми задачу <ссылка или текст>.
Покажи, какие сведения придётся вручную добавлять к «ссылка на задачу — сделай»
и где закрепить их в инструкциях, документации или критериях приёмки.
```

Синтаксис прямого вызова зависит от клиента: например, `$ai-ready-check` в Codex или `/ai-ready-check` в Claude Code. В обычном текстовом запросе можно просто назвать скилл.

Пример результата: [отчёт по условному проекту](examples/ai-ready-report.md). Полные критерии: [чек-лист](skills/ai-ready-check/references/checklist.md).

## Структура

| Путь | Назначение |
|---|---|
| `skills/<name>/SKILL.md` | описание применения и процедура для агента |
| `skills/<name>/references/` | критерии, примеры и справочные материалы |
| `skills/<name>/agents/openai.yaml` | необязательные метаданные интерфейса Codex; аудит от них не зависит |
| `examples/` | примеры результатов для читателя |
| `scripts/validate_skills.py` | проверка структуры, метаданных и локальных Markdown-ссылок |

## Развитие

Новые скиллы добавляются под повторяющуюся полезную работу. Не нужно устанавливать весь будущий каталог: выбирайте нужные процедуры. Как предложить улучшение — в [CONTRIBUTING.md](CONTRIBUTING.md).
